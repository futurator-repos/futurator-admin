## 0. Why (one paragraph of context)

Three generations of per-story VQA failures (dino1: judged the starter page;
pacman1: DEV invented demo harnesses; pacman2: viewport showed a SIBLING's
preview feature — judge graded the wrong pixels) share one root: a story
worktree contains a partial world, and a static one-shot screenshot at
scroll-0 cannot adaptively find the story's surface. Decision: **judged VQA
moves to the wave gate** (the merge candidate is the first place the real
integrated product exists), per-story keeps only a cheap boot smoke, and the
verifier becomes **dynamic/agentic** (evidence-gathering → verifiability gate
→ judge panel → triage → capped fixer → fix-forward). Code-quality gates
(eslint/prettier/knip/husky) join the wave gate, scaled by plan rigor.
Knowledge compiler + REFLECTOR consume VQA outcomes. NO HARDCODING — no
domain keywords, no per-example logic; everything keys off registry metadata,
plan rigor, story rows, and the `@generated`/feature-registry conventions.

## 2. Target design

### 2.1 Story level (M3) — smoke only, no judging

`review-runtime` becomes `story-smoke`:

- KEEP: generate-wiring pre-boot, port drain/kill, dev-server boot via
  qaContext framework-detect, devserver.log capture, PAGE_STATE
  classification (rendered|blank|error-overlay), turbopack-corruption
  recovery path (blank/error ⇒ env feedback into the existing retry loop
  with the devserver.log tail — this caught real infra bugs; keep verbatim).
- KEEP: one screenshot, uploaded to S3 (operator evidence + DEV sanity),
  attached to events/log. NO judge call, NO AC evaluation, NO
  story-vqa-failed / story-vqa-unverifiable cards, NO ac-coverage-gap cards
  for browser ACs (browser ACs without suite tests are the DESIGNED path —
  delete that card emission for needsBrowser ACs; keep it for non-browser
  ACs without tests if that path exists).
- Retry-loop condition: only PAGE_STATE blank/error-overlay (environment)
  re-enters the fix cycle, with the existing environment-fix prompt section.
  Judged-AC failures no longer exist at story level.
- DEV still emits VISUAL_TESTS / judge blocks (plan-level QA + wave VQA
  consume them). The DEV prompt's VQA-feedback sections remain (they now
  arrive via wave handoffs / fix stories instead).
- Token/time effect: stories lose the judge tail; expect ~1–2 min/story
  saved and zero judged false-negatives in-story.

### 2.3 Wave gate VQA (M2) — new module `daemon/lib/wave-vqa-runner.mjs`

Runs INSIDE the gate, after postMergeValidationCmd + quality gates pass and
regenerated/mechanical commits land, BEFORE green advance. Skipped when:
rigor === 'prototype' (gate already skipped), no browser ACs in the wave's
stories, or boilerplate has no `qaContext`.

Inputs (handler fetches): epic row → wave stories (criteria, touchPoints,
title, description), plan rigor, qaContext, candidateDir, planId/epicId/waveNumber.

Stages (each streams a `status` event via the existing `waveLog` tee):

1. **boot** — extract the dev-server boot/drain/PAGE_STATE bash from
   review-runtime into a shared helper `daemon/lib/dev-server-boot.mjs`
   (used by both story-smoke and wave VQA; framework-detect from qaContext;
   returns { ok, pageState, devserverLogTail, port }). no-boot/blank ⇒
   DETERMINISTIC failure ⇒ treat exactly like build failure (build-fix
   agent path, blocking).
2. **evidence** (agentic) — spawn claude CLI (mirror the
   `fixWaveMergeBuildOnce` spawn shape: `-p`, bypassPermissions, model
   `WAVE_VQA_EVIDENCE_MODEL || claude-haiku-4-5*`, cwd candidateDir,
   12m timeout, OAuth pre-spawn check + 1 recovery retry, `infra` tagging).
   Prompt contract: given JSON list of { storyId, featureSlugs[] (derived:
   touchPoints matching `src/features/(.+)\.feature\.tsx`), browserAcs[] },
   use Playwright (installed on host; `npx playwright screenshot` and/or
   a small Node script with playwright lib — daemon already deps playwright
   for L2 flows) to capture per-story evidence: try
   `http://localhost:PORT/?feature=<slug>` first, else root +
   `#feature-<slug>` scroll, else full-page; ALSO capture composed root.
   MUST output between `---EVIDENCE_JSON---` fences:
   `[{ storyId, acId, screenshotPath, capturedSurface: '<what is actually
in frame, one sentence>', verifiable: bool, whyNotVerifiable? }]`.
   Upload shots to S3 `review-screenshots/wave-<epicId>-<waveNumber>/...`
   (reuse the s3 cp pattern from review-runtime). Evidence agent CANNOT
   mutate the repo (instruct: read-only + /tmp only; enforce by running
   `git status --porcelain` after and resetting/failing if dirty).
3. **verifiability gate** — ACs the evidence agent marked
   `verifiable:false` are routed OUT before judging: verdict UNVERIFIABLE,
   non-blocking, listed in the report (no card unless ALL of a story's ACs
   are unverifiable → one LOW `wave-vqa-unverifiable` card with the
   capturedSurface explanations).
4. **judge panel** — per verifiable AC, N independent claude `-p` haiku
   calls (N by rigor: mvp=2, production=3) with DIFFERENT lenses
   (strict-literal reading; layout/composition) over the SAME screenshot
   (pass image via the CLI's file reference — judge prompt mirrors
   review-runtime's current judge with the PASS/FAIL/UNCERTAIN+confidence
   contract). Majority FAIL with avg confidence ≥ threshold (reuse current
   threshold) ⇒ CONFIRMED FAIL; disagreement ⇒ UNCERTAIN (non-blocking,
   reported). Run panel calls in parallel (Promise.all) — they're cheap.
5. **triage** (agentic, sonnet) — for confirmed FAILs ONLY: one call,
   input = failures + evidence + the wave's merged diff stat + story
   touchPoints; output fenced JSON per failure:
   `{ acId, classification: 'code-bug'|'environment'|'ac-wording',
suspectedFiles[], handoffSummary }`.
6. **fix round** (agentic, capped by rigor: mvp=1, production=2 with model
   escalation round 2) — for `code-bug` failures: spawn VQA-fixer in the
   CANDIDATE (mirror fixWaveMergeBuild spawn + rules). Fixer receives the
   **handoff packet** (§2.4). After fixer: re-run quality+build+test
   (full postMergeValidationCmd) + re-run evidence+judge for ONLY the
   previously-failing ACs. Pass ⇒ `git add -A` + commit
   `wave <n>: vqa-fix — <acIds>\n\n<reasoning + AC list>` (audited).
   `environment` ⇒ dev-server cache clean + reboot + re-evidence (once).
   `ac-wording` ⇒ card `ac-contested` (existing category), non-blocking.
7. **fix-forward** (judged failures NEVER block green) — failures still
   confirmed after the capped rounds: ADVANCE GREEN ANYWAY, then:
   a. write attention card `wave-vqa-failed` (MEDIUM, dedupKey
   `wave-vqa:<planId>:<epicId>:<wave>:<storyId>`) carrying the handoff
   packet (context) + screenshot URL + "Retry wave gate" wiring
   (epicId+waveNumber in context like wave-build-failed).
   b. **auto-mint a fix story** (§2.5) — at mvp+ rigor, max ONE per
   (owning story); recurrence ⇒ operator card only (escalation ladder
   end). Deterministic failures (boot/build/test) keep today's blocking
   behavior unchanged.
8. **report + knowledge** (§2.6) — always, pass or fail.

Module signature (testable like wave-merge-runner: inject spawners/shell/git):

```js
runWaveVqa({ candidateDir, stories, rigor, qaContext, planId, epicId,
  waveNumber, appId, spawnEvidence, spawnJudge, spawnTriage, spawnFixer,
  shell, git, writeAttention, log, s3Prefix })
→ { outcome: 'pass'|'fixed'|'fix-forward'|'skipped'|'env-blocked',
    verdicts[], fixesApplied[], fixForward[], reportPath }
```

Handler wires real spawners (new fns in agent-daemon.mjs beside
fixWaveMergeBuild, sharing its auth-recovery wrapper — extract a generic
`spawnGateAgent({prompt, model, cwd, timeoutMs, readOnly})` helper to stop
copy-pasting the spawn/timeout/infra-tagging block a third time).

Call site in `wave-merge-runner.mjs`: after the regenerated-files commit,
before step 4 (green advance). `runWaveMerge` gains optional `runVqa` hook
(undefined ⇒ skip; daemon passes it when rigor!=='prototype' && qaContext
&& wave has browser ACs). On `env-blocked` ⇒ return
`{ outcome: 'wave-build-failed', ... }` (reuses ALL existing retry/attention
machinery). On `fix-forward` ⇒ proceed to advance; the runner result gains
`vqa` field persisted in `waveMergeResult` for the UI.

### 2.4 The handoff packet (REQUIRED shape — the "proper handoff instructions")

Written to `\.pipeline/vqa-handoffs/<acId>.json` in the candidate (so it
ships in green — evidence preserved per invariant I4), embedded in the
attention card `context.handoff`, in the fix-story description, and in the
fixer prompt:

```json
{
  "storyId": "...",
  "storyTitle": "...",
  "acId": "AC-S8-1",
  "acText": "...",
  "verdicts": [
    {
      "lens": "strict",
      "verdict": "FAIL",
      "confidence": 0.9,
      "observation": "what the judge actually saw"
    }
  ],
  "evidence": {
    "screenshotUrl": "https://...",
    "capturedSurface": "...",
    "pageState": "rendered",
    "url": "http://localhost:3000/?feature=hud-preview"
  },
  "triage": {
    "classification": "code-bug",
    "suspectedFiles": ["src/..."],
    "summary": "expected X, observed Y, likely Z"
  },
  "attempts": [{ "round": 1, "fixer": "summary of attempted fix", "result": "still-failing" }],
  "expected": "verbatim AC",
  "observed": "judge consensus observation",
  "verifyCommand": "boot dev server; screenshot http://localhost:PORT/?feature=<slug>; AC must hold on the idle frame"
}
```

Fixer prompt rules (mirror build-fix rules + add): smallest change
preserving every story's intent; never weaken/delete test ASSERTIONS (infra
repairs preserving intent allowed); read the owning story's
`.context/wave-*-story-*.md`; you MAY re-run the verify command yourself;
do NOT git commit/push; do NOT touch `package.json`/lockfiles/configs/
`@generated` files (regenerate via the script instead).

### 2.6 Knowledge compiler + REFLECTOR integration

- **Wave VQA report** `\.context/wave-<n>-vqa-report.md` written in the
  candidate BEFORE the final commit (lands in green): per-AC verdict table,
  capturedSurface notes, fixes applied + reasoning, fix-forward list,

  via the repo; the per-story COMPILER (which summarizes the worktree) will

  var `REFLECTIONS_TABLE`/similar in sst.config.ts + reflections service at
  impl time; daemon already has broad DDB access). Best-effort,
  never blocks the gate. REFLECTOR/operator promotes via existing inbox.
- **graph-sync**: no change needed — wave report lives in `.context/`
  (committed); if `.context` is excluded from compile, ALSO append a short
  entry to `knowledge/waves.md` (check what the COMPILER/graph-sync actually
  index at impl time and pick the indexed location).

### Deviations from §2 (all intent-preserving, recorded once)

1. **Generated page filter is client-side** (`useSearchParams` under
   `<Suspense>`), not a server-component `searchParams` read — a server read
   forces the route dynamic and would break `output: 'export'` builds; the
   template repo's next.config could not be inspected (daemon-only deploy
   key). Behavior identical for the dev-server VQA path.
2. **Handoff packets live at `.context/vqa-handoffs/<acId>.json`**, not
   `.pipeline/` — the template ships `.pipeline/.gitignore` (`*`), so
   nothing there can "ship in green". `.context/` is the committed location
   (same place as story context packs); invariant I4 intent preserved.
3. **Gate-registry snapshot** — the planned "VERIFY at impl" found the
   `sst-env-shared/boilerplate-registry-snapshot.mjs` import was NEVER
   generated (hardcoded fallback ran since 2026-05-19). Fixed properly:
   `scripts/generate-gate-registry-snapshot.mjs` writes
   `daemon/lib/boilerplate-gate-registry.json` (committed, ships with every
   rsync) and `gate-registry-snapshot.test.ts` is the drift alarm. ONE
   source of truth = the TS registry.
4. **Husky pre-commit chains the PR-41 frozen-file guard** — discovered
   dormant (`.husky/pre-commit-frozen` is not a hook name git invokes, and
   nothing ever ran `husky install`). The new template `prepare: "husky"` +
   `.husky/pre-commit` activates it; mechanical lint-staged half no-ops
   below production rigor and can never fail a commit. Agent worktrees skip
   hooks entirely (no npm prepare there → no `.husky/_`).
5. **Wave VQA boots on `qaContext.defaultPort + 700`** — story review
   servers use the default port on the same host; draining a shared port
   would kill a sibling story's server mid-screenshot.
6. **Fix-story mint happens BEFORE the gate job flips COMPLETED** — the
   reducer advances/completes the epic on the first tick that sees a
   terminal gate; stories appended after that read would never launch.
   Append via `list_append`, never a full-array write.
7. **Story smoke kept step id `review-runtime`** — the daemon's marker
   consumers (story-vqa-skipped etc.) need zero changes: the smoke emits
   only the SKIPPED markers + its own `STORY_SMOKE_FAILED`, so the judged
   card paths simply never fire while in-flight old-style jobs stay fully
   supported.
8. **Fixer commits before re-judge, reverts on zero improvement** — the
   evidence agent's read-only enforcement hard-resets ANY dirt, so a fix
   must be committed (it is validation-green by then) before re-capture;
   if the re-judge shows no AC improved, the commit is reverted
   (horse-runner1 rule: no unjustified mutations survive).
