# Story 19.5: Agent commit composer (shared by pipeline-v2 + party-push)

Status: DONE (2026-05-21)

## Story

As an engineer composing system-driven commits across multiple agent classes,
I want one helper that builds canonical commit messages with v2.5 §23 trailers (Plan-Id / Plan / Epic-Id / Wave / Session-Id / Project / Round / Trigger / Participants),
so that `git log --grep="Plan-Id: …"` and `git log --grep="Session-Id: …"` work uniformly across pipeline-v2 and party-push commits.

## Acceptance Criteria

1. New file `daemon/pipelines/lib/agent-commit-composer.mjs` exports:
   - `composeAgentCommit(input: PipelineV2Input | PartyInput) → { message, coAuthors, warnings }`
   - `validateTitle(title) → { clean, warnings }`
   - `validateSummary(summary) → { clean, lines }`
   - `sanitize(s) → string`
2. `sanitize` strips C0 control chars (`\x00–\x1f`) + DEL (`\x7f`) + zero-width Unicode (`U+200B–U+200D`, `U+200E`, `U+200F`, `U+FEFF`) — per §12.1.3 fix. **Tests must include `'hello\x00world'` and `'hello​world'` fixtures.**
3. `validateTitle` returns warnings array with codes: `title-empty`, `title-noise` (matches `Update`/`Change`/`Fix`/`WIP`/`untitled` solo or empty), `title-too-short` (<3 words after sanitize).
4. `composeAgentCommit({kind: 'pipeline', ...})` produces a message matching the current `commit-metadata.ts` shape: `story: <id> — <title>` subject, body, `Agent: DEV`, `Story:`, `Plan-Id:`, `Plan:`, `Epic-Id:`, `Wave:` trailers, optional `Skills-Used` + `Skills-Manifest-Sha`, `🤖 Generated with Claude Code via the Futurator pipeline` footer.
5. `composeAgentCommit({kind: 'party', ...})` produces: `party(<projectId>/round-<N>): <title>` subject, body, `Agent: PARTY-ORCHESTRATOR`, `Session-Id:`, `Project:`, `Round:`, `Trigger:`, optional `Debate:`, `Participants:`, `Co-authored-by:` lines per participant, `🤖 Generated by Futurator Party Mode` footer.
6. `coAuthors` is returned as a separate array (not just embedded in `message`) so callers can pass via `git commit -m "$msg" -m "Co-authored-by: ..."` if preferred.
7. **Required tests** (`daemon/pipelines/lib/__tests__/agent-commit-composer.test.mjs`):
   - `validateTitle` flags empty / noise / short titles; passes normal titles
   - `sanitize` strips control + zero-width chars (with explicit `'hello\x00world'` + `'hello​world'` fixtures per §12.1.3)
   - `composeAgentCommit` pipeline shape: subject correct, all v2.5 §23 trailer keys present, footer present
   - `composeAgentCommit` party shape: subject correct, Session-Id + Project + Round + Trigger present, co-authors generated from participants, BMad Master always first
   - Party with empty participants emits no co-authors
   - Co-author email collision case (`'John'` and `'John (PM)'` both → `party+john@...`): test that the warning fires (per §12.4 risk 31 — implementation can deduplicate-and-warn or rename; the test asserts the warning)
8. Typecheck stays at baseline.

## Implementation notes (2026-05-21)

- Module at `daemon/pipelines/lib/agent-commit-composer.mjs`.
- **Sanitize regex bug-fix during implementation**: my first cut stripped `\n` along with the C0 range, which broke `validateSummary`'s line-splitting. The §12.1.3 spec calls for stripping control chars but commit bodies legitimately contain newlines and tabs. Fixed the regex to `/[\x00-\x08\x0b-\x1f\x7f]/g` — keeps `\n` (0x0a) and `\t` (0x09), strips everything else in the C0 range plus DEL. Zero-width Unicode strip (U+200B–U+200F + U+FEFF) is a separate replace.
- 25 tests pass: 6 sanitize tests (including the explicit `'hello\x00world'` and `'hello​world'` fixtures from AC 2), 4 validateTitle tests, 2 validateSummary tests, 5 pipeline-shape tests (subject, all v2.5 §23 trailer keys, footer, no coAuthors, optional skill lines), 6 party-shape tests (subject, trailers, co-authors-order, footer, empty-participants, collision warning), 2 input-validation tests.
- The collision-case test (per §12.4 risk 31) uses two literal `'John'` participants — both slugify to `john`; first wins, second drops + emits `coauthor-collision:john` warning.
- Story 20.13 (commit-metadata.ts backfill) will diff this composer's output against the current pipeline output to verify byte-identical messages.
