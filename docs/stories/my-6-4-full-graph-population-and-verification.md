6. A verification query confirms: vector index `knowledge_index` contains embeddings for all nodes

8. Wiki is backed up to S3 at `s3://futurator-ai-website/knowledge-live/{projectId}/`
9. `futurator-project-registry` DynamoDB table is updated with `knowledgeGraph` metadata: `nodeCount`, `edgeCount`, `lastCompileAt`, `memgraphSynced: true`

## Dev Notes

### Architecture Context

This is the capstone story of the Brownfield Bootstrap epic (Epic 6). It takes all the wiki articles generated by Stories 6.1 (code scan), 6.2 (dependency extraction), and 6.3 (decision inference) and performs the full Memgraph population — embedding every article, creating every edge, and running verification to ensure the graph is complete and queryable.

**After this story completes, the user can immediately use the Conversational Agent (Epic 5) on the bootstrapped project.** This is the moment where "talk to your app" becomes real for existing codebases.

### Graph Sync Mechanics

The `graph-sync.mjs` script (from Story 1.5) handles the heavy lifting. The `--full-resync` flag bypasses incremental hash checking and processes every article:

1. Reads all `.md` files in `knowledge/` recursively
2. Parses frontmatter (YAML) to extract node properties
3. Extracts first 200 chars of `## Purpose` section as `summary`
4. Calls Voyage AI API (`voyage-3-large`) to generate 1024-dim embeddings
5. Upserts into Memgraph via Bolt protocol: `MERGE (n:Node {nodeId: $nodeId}) SET n += $properties`
6. Parses `[[wikilinks]]` from each section, maps section headers to edge types per architecture doc section 3.2
7. Creates edges: `MERGE (a:Node {nodeId: $from})-[:DEPENDS_ON]->(b:Node {nodeId: $to})`
8. Updates `.mycelium/compile-state.json` with MD5 hashes of all processed articles

### Verification Query Details

The verification step prevents silent failures that would leave an empty or incomplete graph. Each query targets a specific failure mode:

| Query              | Detects                                                          | Severity |
| ------------------ | ---------------------------------------------------------------- | -------- |
| Node count match   | Missing articles (sync skipped files)                            | Critical |
| Edge count > 0     | Wikilink parsing failure                                         | Critical |
| Embedding coverage | Voyage AI API failures                                           | Critical |
| Orphan detection   | Articles with no connections (may be valid for standalone utils) | Warning  |
| Sample GraphRAG    | End-to-end search failure                                        | Critical |

### Cost Estimate

For a typical brownfield project with 200 articles:

- Voyage AI embeddings: ~200 API calls x ~$0.0001 = ~$0.02
- Memgraph upserts: local, $0
- S3 sync: negligible
- Total for this story: ~$0.02-0.05

Combined with Story 6.1 (~$0.50-2.00), the full bootstrap pipeline costs ~$0.52-2.05 per project.

### DynamoDB Project Registry Update

The `knowledgeGraph` field added to `futurator-project-registry` enables the admin UI and other agents to know:

- Whether a project has been bootstrapped into the knowledge graph
- How large the graph is (node/edge counts)
- When it was last compiled
- Whether Memgraph is in sync with the wiki files

```typescript
interface ProjectRegistry {
  // ... existing fields unchanged ...
  knowledgeGraph?: {
    nodeCount: number;
    edgeCount: number;
    lastCompileAt: string; // ISO 8601 timestamp
    lastLintAt?: string;
    lastPruneAt?: string;
    memgraphSynced: boolean;
  };
}
```
